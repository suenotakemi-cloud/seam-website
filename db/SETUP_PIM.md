# SEAM 商品マスタ統一（PIM）— 設定手順と使い方

メーカーごとにバラバラな形式で届く商品データ（CSV / Excel）を、
**JAN・商品名・価格・税込/税抜・内容量・画像(最大5枚・webp)** の1つの形に揃えて保存し、
同じ形で出力する仕組みです。スマホで JAN を読んで写真を登録する画面も含みます。

- スマホ登録: **https://seam.site/pim/**（JANスキャン → 商品呼び出し → 写真5枚）
- PC 取り込み・出力: **https://seam.site/pim/import.html**
- SEAM 管理（ディーラーアカウントの発行）: **https://seam.site/pim/admin.html**
- どれも検索エンジンには出ません（noindex）。
- **1ディーラー = 1アカウント（ID + パスワード）**。ディーラーのスタッフは全員同じ ID を使い、端末ごとに担当者名を名乗ります。商品・写真・注意はアカウントごとに完全に分かれ、他のディーラーのデータは見えません。
- 管理画面だけは診断ダッシュボードと同じ `ADMIN_KEY` でログインします。

---

## 仕組み（全体像）

```
メーカーCSV/Excel ─▶ pim/import.html（列を合わせて統一形に整形・JAN重複を検出）
                          │  保存                     │ 注意（重複は登録しない）
                          ▼                           ▼
                    D1 seam-db: pim_products     D1: pim_issues → 画面で「どちらを残す」
                          ▲
スマホ pim/index.html ─ JAN読取 → 商品呼び出し → 写真（何形式でも webp に変換）→ R2 PRODUCT_IMAGES
                          │
                          ▼
                    /api/pim/export → 統一CSV / JSON（画像は https://seam.site/pim-img/… のURL）
```

コード側（`db/pim-schema.sql` / `functions/api/pim/*` / `functions/pim-img/` / `pim/*.html` / `js/pim-*.js`）はデプロイ済みです。
あとは **Cloudflare 側で保存先を繋ぐ設定だけ** が必要です。

---

## 設定手順（Cloudflare ダッシュボード）

### ① D1（商品台帳）— 診断ダッシュボードで作った `seam-db` をそのまま使う
- まだ無ければ `db/SETUP_DASHBOARD.md` の①〜③を先に。
- テーブルは **初回アクセス時に自動で作られます**（`CREATE TABLE IF NOT EXISTS`）。
  手動で入れたい場合は `seam-db` → **Console** に `db/pim-schema.sql` を貼って Execute。

### ② R2（画像の実体）を作る
1. Cloudflare → **R2 Object Storage** → **Create bucket** → 名前 **`seam-product-images`**
2. **Workers & Pages** → サイト **seam-website** → **Settings** → **Functions** → **R2 bucket bindings** → **Add binding**
   - Variable name: **`PRODUCT_IMAGES`**（大文字・この名前のまま）
   - R2 bucket: `seam-product-images`
3. 保存

> R2 が未設定でも商品データの取り込み・出力は動きます。写真の保存だけができません（画面に案内が出ます）。

### ③ 管理キー
- 診断ダッシュボードの **`ADMIN_KEY`**（Environment variables）をそのまま使います。未設定なら `db/SETUP_DASHBOARD.md` の④。
- ログインのトークンはこの鍵で署名します。別にしたければ **`PIM_SECRET`**（長いランダム文字列）を足してください（足すと既存のログインは全部無効になります）。

### ③-1 最初から入っているテスト用アカウント
- アカウントが1つも無い状態で最初に API が動いたとき、テスト用に **ID `takemi` / パスワード `sueno`** が自動で作られます（スマホですぐ試せるように）。
- **実証実験が終わったら必ず** `/pim/admin.html` で「PW再設定」か「停止」をしてください（パスワードが短く、リポジトリにも書いてあるため）。

### ③-2 ディーラーのアカウントを発行する
1. `/pim/admin.html` を管理キーで開く
2. 「アカウントを発行する」に ID（英数字）・ディーラー名・初期パスワード（自動生成可）を入れて発行
3. 表示された ID とパスワードを、`/pim/`（スマホ）と `/pim/import.html`（PC）の URL と一緒にディーラーへ安全な方法で伝える
- 新しいディーラーが増えたら、同じ手順で発行するだけです。

### ④ 再デプロイ
- **Deployments** → 最新の **⋯** → **Retry deployment**（または次回の push で自動反映）

### （任意）webp 以外が届いたときのサーバ側変換
- ブラウザ側で必ず webp に変換して送るので通常は不要です。
- 古い端末からの保険として、Cloudflare Images の **Images binding**（Variable name `IMAGES`）を足すと、サーバ側でも変換します。

## 使い方

### A. メーカーの CSV / Excel を取り込む（PC）
1. `/pim/import.html` → **取り込み** タブ → ファイルをドロップ
   - 文字コード（UTF-8 / UTF-16 / Shift_JIS）・区切り（カンマ / タブ）・Excel のシートは自動判定
2. **列を合わせる** … 見出しの言葉が違っても自動で当てます（例: 「EC表示名」→商品名、「標準売上単価」→価格、「上代単価」→上代）。違っていれば直す。
   - 価格列が税込か税抜かは、列名・値に「税込/税抜」があればそれを優先。無ければここで選ぶ。
   - 内容量の列が無いときは、商品名の「250ml」「1Kg」などから取り出します。単位なしの数字（「〇〇 250」）は商品名の語（シャンプー→ml、トリートメント→g）から推定し、**注意** に印を付けます。
3. **確認する** … 揃えた結果の表と、注意の内訳（JANチェックデジット不一致・価格が読めない・単位推定 など）
4. **JANが被っているもの** … 登録済みと同じ JAN / 同じファイル内で重複している JAN を並べて表示。
   - 「登録済みを残す」「届いた方で上書き」「この行を採用」を選ぶ
   - **決めなかったものは登録されず「注意」タブに積まれます**（あとから決められます）
5. **保存** … 300件ずつ保存。履歴が下に残ります。

### B. スマホで写真を登録する（iPhone / Android）
1. `/pim/` を開く（ホーム画面に追加するとアプリのように使えます）→ ディーラーの ID・パスワード・担当者名
2. カメラに商品のバーコードをかざす → 商品が呼び出される。**写真が登録済みなら、上に大きく表示され、サムネイルで切り替え・タップで全画面**（誰が撮ったか・サイズも表示）。未登録の JAN なら商品名だけ入れて登録 → そのまま写真へ（**新商品はこの流れで随時追加できます**）
3. 写真の枠をタップ → **「カメラで撮る」か「写真・ファイルから選ぶ」** → 1枚保存されると次の枠が光る → 繰り返し（最大5枚・1枚目がメイン）
4. **次の商品をスキャン**
- 写真は端末側で長辺 1600px・webp に変換してから送るので、通信量も保存形式も揃います。
- 写真をタップ → 撮り直し / 差し替え / 削除（削除すると後ろの写真が前に詰まります）

### B-2. 写真を揃えるしくみ（ガイド付きカメラ・白背景）
- 枠をタップ → **「ガイド付きカメラで撮る」** でアプリ内のカメラが開き、次の目印が重なります。
  - 外枠 … 保存される範囲（正方形）
  - 黄色の点線 … 商品を収める範囲（縦 78%・横 70%）。ここいっぱいに入れると、どの商品も同じ大きさに写ります
  - 下の黄色い線 … 商品の底を合わせる位置
  - 商品のシルエット … ボトル / ジャー・缶 / チューブ・袋 / 枠のみ から選べます（端末に記憶）
  - 「↑ キャップ・上を上に」・中心線・水平器（端末の傾きを表示。対応端末のみ）
  - 何枚目かで指示が変わります: 1 正面 / 2 裏面（成分表示）/ 3 斜め・側面 / 4 キャップ・口元 / 5 手に持って大きさ
- 保存は必ず **1200×1200 の正方形** です。アルバムの写真やメーカーの画像も、白で余白を足して正方形にします。
- **背景を白に**（標準 / 強 / 弱 / なし）… 白い紙・シートの上で撮る前提で、縁からつながる「ほぼ白」の部分を純白にし、紙の色かぶり（黄み・青み）も補正します。影が残るときは「強」に。背景が白くない写真は判定して触りません。
  - これは AI の切り抜きではありません。柄のある背景や机の上で撮ると白くなりません。**必ず白い紙・白いシートの上で撮ってください**。
  - AI による完全な切り抜き（remove.bg などの外部サービス）が必要になったら、サーバ側に組み込めます（有料・別途）。
- 端末のカメラアプリで撮りたいときは撮影画面の「端末カメラ」から。その場合も正方形・白背景の加工はかかりますが、構図は自分で合わせることになります。

### C. メーカーから届いた画像フォルダをまとめて登録（PC）
- **画像まとめ登録** タブにフォルダの中身をドロップ。ファイル名の JAN と枚目を読みます。
  - `4901275230122.jpg` → 1枚目 / `4901275230122_2.png` / `4901275230122-3.jpeg` / `4901275230122 (4).heic`
  - 同じ JAN で枚目の無いファイルが複数あれば、名前順に 1, 2, 3… と入ります
- jpg / png / gif / bmp / webp / avif / heic（Safari）…何で来ても保存は webp。既定で正方形 1200px・白背景に揃えます（画面のチェックで外せます）。

### D. 出力する（PC・スマホどちらからでも）
- PC: **出力** タブ ／ スマホ: 右上「設定」→「データを出力する」。同じ CSV が落ちます。
- **出力** タブ → 3 種類。メーカー・写真あり/なしで絞れます。いずれも UTF-8（BOM 付き）で Excel で開けます。
  1. **取り込んだ CSV の形 ＋ 画像1〜5**（EC 向け）… 最後に取り込んだファイルの列をそのまま（菊池 CSV なら 商品コード, EC表示名, JAN, … の 22 列）出し、右端に `画像1〜画像5, 画像枚数` を足します。EC 側は **商品コード（商品ID）** で突き合わせます。スマホで新規登録した商品は、対応の分かる列（商品コード・JAN・商品名・価格・メーカーなど）だけ埋まります。
  2. **商品ID・JAN・商品名・画像1〜5 だけ** … EC 側が既に商品を持っていて、画像だけ足したいとき。
  3. **統一フォーマット CSV / JSON** … 下記の固定列。
- 列（固定）: `JAN, 商品名, 価格(税抜), 価格(税込), 入力価格の税区分, 税率(%), 内容量, 単位, 内容量表記, 上代(税抜), 仕入価格, メーカー, ブランド, カテゴリ, 商品説明, 元商品コード, 画像1〜5, 画像枚数, 更新日時`
- 画像は `https://seam.site/pim-img/products/<アカウント番号>/<JAN>/<枚目>.webp?v=…` の URL。EC 側からそのまま参照できます（CORS 許可済み）。
- **写真を zip でまとめて落とす**（PC「出力」タブの下）… ファイル名は **JAN_枚目.webp** か **商品ID_枚目.webp** を選べます。「商品ごとにフォルダ」「1枚目だけ」も可。zip の中に `list.csv`（ファイル名・商品ID・JAN・商品名・枚目）が入ります。zip はブラウザ側で作るので枚数の上限はありません（Chrome / Edge は保存先を選んで 1 つの zip に直接書き出し。他のブラウザは約 300MB ごとに分割）。

### E. 撮影キュー（スマホ）— バーコードを読まずに順番に撮る
- スキャン画面の「撮影キュー」に、**写真なし／1〜4枚（2周目）／撮り直し** の商品が **メーカー → ブランド → 商品名** の順で並びます。メーカーで絞れます。
- 「先頭から始める」→ 商品画面 → 撮る → **「次の商品へ →」** で次が出ます。端末ごとに「続きから」も覚えます。
- 複数人で回すときは **メーカーで分担**（田中さんはアリミノ、佐藤さんはミルボン…）すると取りこぼしと重複がなくなります。
- 分担しなくても、誰かが開いている商品は **10分間「撮影中」** になり、他の人の撮影キューから外れます（同じ商品を2人で撮るムダを防ぐ）。開くと「〇〇さんもこの商品を開いています」と出ることがあります。閉じる・次へ進む・アプリを閉じると解除。忘れても10分で自動解除。

### F. 進捗（PC「進捗」タブ・管理画面「進捗」ボタン）
- 商品数・写真あり/なし・5枚そろい・未検品・撮り直し・注意、日別（14日）、担当者別（今日/累計）、メーカー別の残りと進み具合。
- 直近7日の1日平均から **残り稼働日数** を出します。初日の数字で日数見積もりの答え合わせができます。

### G. 写真の検品（PC「検品」タブ）
- 未検品の写真を並べて **OK / 撮り直し（理由）** を付けます。「表示中をすべて OK」でまとめて処理。
- 「撮り直し」はスマホの撮影キュー（撮り直し）に出て、商品画面のその枠が**赤く**なり理由が表示されます。撮り直すと印は自動で消えます。
- EC に載せる前の関所として、写真なし → 撮影 → 検品 OK の順で回してください。

### H. 更新取り込み（メーカーの改定 CSV）
- 取り込み画面の「列を合わせる」で **更新取り込み** を選び、上書きする列（価格・上代・商品名 …）にチェック。
- 登録済み商品はその列だけ上書きし、**写真・ほかの列はそのまま**。未登録の JAN は新規として追加。重複の確認は出ません。
- 「取り込んだ CSV の形＋画像」の出力は、更新取り込みの列が少なくても元の 22 列を保ちます（更新した値はその列に反映）。

### G2. 商品写真ガイド（分類ごと・5 枚）
- `pim/photo-guide.html`: ディーラー EC（ガモウ関西 G SELECT など）・Amazon と同じ見え方に揃えるためのガイド。ディーラーの分類（カテゴリ大 > 中 > 小・菊池 スマイルの全 117 分類）ごとに「容器の形（27 種）・1枚目でまず読ませるもの・注意」を決め、5 枚の角度をイラストで示す。Amazon 品質の 8 か条・NG 例つき。印刷可。
- 分類 → 形の対応は `pim/photo-guide.js` の `CATS`（分類名は CSV のまま。無い分類は商品名から推定）。スマホのカメラ画面はその形の「n枚目: …」と「まず読ませるもの」を出し、「📖 ガイド」で該当ページが開く。手で形を変えることもできる。
- バーコードを読んだ商品画面には **「取り込んだデータ（全項目）」** が出る（取り込んだ CSV の行を列順のまま。ディーラーの CSV の形が取り込みの基準）。

### H2. メーカーのデータ（空欄だけ埋める）— 全国のディーラー共通の「ベースを守る」取り込み
- 考え方: **ディーラーの商品データ（菊池なら スマイル の CSV）がベース**。メーカーから届く商品データは形がバラバラなので、それでベースを壊さない。
- 取り込み画面の「列を合わせる」で **メーカーのデータ（空欄だけ埋める）** を選ぶと:
  - 登録済みの商品は **商品名・商品コード（商品ID）を絶対に変えず**、空いている項目（価格＝税抜・税込とも空のときだけ／上代／仕入価格／内容量／メーカー／ブランド／カテゴリ／商品説明）だけを埋める。元の CSV の行（`raw`）も触らない。
  - 「画像」列（URL。複数列や 1 マスに複数 URL も可）があれば、保存のあと続けて写真を取り寄せ、**空いている枠に足す**（登録済みの写真は置き換えない。同じ URL・同じ写真は二度入れない。5 枚そろっていれば入れない）。
  - **ベースに無い JAN は登録しない**（記録に一覧が出る）。「ベースに無い JAN も新規として追加する」に ✓ したときだけ追加（商品名の無い行は追加しない）。
  - **JAN と画像 URL だけ**のファイルでも取り込める（商品名の列は不要）。
- 同じ見出しのファイルを次に受信箱（メール転送）で受け取ると、この設定のまま自動で取り込まれる（写真の取り寄せだけは PC の取り込み画面で同じファイルを読み込んで行う）。
- 取り込み履歴では「空欄埋め」と出て、**取り消す** で埋めた値は空に戻り、追加した商品は消える（触っていない商品は何も起きない）。
- 「画像まとめ登録」（フォルダをまとめて）も既定で **空いている枠に足す**（ファイル名の番号は見ない・同じ写真は入れない）。番号どおりに差し替えたいときだけ「上書き」に ✓。
- 画像 URL の取り寄せは `/api/pim/fetch?url=…`（ログイン済みのみ。https の画像だけ・12MB まで・社内アドレスには行かない）。縮小・webp・自動チェック・サムネはいつも通りブラウザ側。

### I. EC 連携の自動化（連携キー）
- 管理画面のアカウント一覧 → **「連携キー発行」** → ディーラーごとの読み取り専用キー（`seam_…`）が出ます。
- EC 側は毎晩 `https://seam.site/api/pim/export?format=source&api_key=<キー>` を取りに来るだけ（`format=images` / `csv` / `json` も可）。書き込みはできません。
- 漏れたら「再発行」で古いキーは即無効、「無効化」で止められます。
- **差分だけ取る**: `…/export?format=source&since=2026-09-01T00:00:00Z&api_key=…`（その日時以降に変わった商品だけ。写真の追加・削除でも商品が「変わった」扱い）。`/api/pim/changes?since_id=<前回の latest_id>&api_key=…` で「変わった JAN の一覧」（`kind=delete` は EC 側でも消す）。
- **Webhook（push）**: 管理画面のアカウント一覧 → **「Webhook」** → EC 側の URL（https）を入れると、商品や写真が変わるたびに `POST {event:'changed', kind, jans:[…], export_url}` を送ります。署名は `x-seam-signature: sha256=HMAC-SHA256(秘密, body)`（秘密は設定時に 1 度だけ表示）。EC 側は届いた JAN だけ取り直せば済み、毎晩の全件取得が要らなくなります。同じ URL のまま OK すると **テスト送信**、最終送信の結果は一覧の Webhook ボタンで確認できます。

### J. 写真の自動チェック（暗い・ピンぼけ・小さい・白飛び）
- スマホ・PC で写真を登録する瞬間に、機械的に **暗い／ピンぼけ／小さい（元が 500px 未満）／白飛び** を見ます。注意があれば「このまま登録する／撮り直す」を聞きます（止めはしません）。ガイド付きカメラでは撮った直後のプレビューに出ます。
- 注意つきで登録した写真は、商品画面の枠に「⚠ 暗い」のように出て、PC の検品タブで **「自動チェックで注意あり」** で絞れます。撮り直す（同じ枠に上げ直す）と消えます。
- 目安なので、黒いボトルや無地の商品で外れることがあります。検品の人が最終判断してください。

### K. 商品名の表記ゆれ（似ている商品名）
- 取り込み時に商品名の表記を揃えます: `250mL`・`250ｍｌ`・`250 ml`・`250cc` → `250ml`、全角英数字 → 半角、半角カナ → 全角、`×` の統一。揃えた行は確認画面の「注意」に「商品名の表記を揃えました(元 → 後)」と出ます。
- **同じメーカーで商品名がほぼ同じなのに JAN が違うもの**（ファイル内どうし・登録済みと）を確認画面に出します。表記ゆれ（同じ商品の二重登録）か、本当に別の商品か（例: `エマルジョン` と `エマルジョン+` は別。`+` は区別します）を見てください。登録は止めません。保存時に「注意」にも残せます（注意タブ → 商品名が似ている）。

### L. 写真の並べ替え・メイン差し替え（スマホ）
- 商品画面で写真をタップ → **「⭐ 1枚目（メイン）にする」「← 前の写真と入れ替える」「→ 後ろの写真と入れ替える」**。削除 → 登録し直しは要りません。検品の印・自動チェックの注意も写真と一緒に動きます。

### M. 担当者一覧と PIN（名前の打ち間違い防止）
- PC「設定」タブ → **担当者一覧** に名前を登録すると、スマホ・PC は自由入力ではなく **名前をタップして選ぶ** 形になります（進捗の担当者別が「田中」「田中 」「たなか」に割れない）。SEAM 管理画面の「担当者」からも代行で登録できます。
- **PIN（4〜6 桁）** を付けた人は、選ぶときに PIN を求めます。共用端末で他人の名前で登録できないようにするためのもの。PIN を忘れたら PC の設定か管理画面で付け直し。
- 一覧に 1 人でも登録があると、サーバ側も「一覧にある名前」からの登録しか受け付けません（一覧に無い名前・停止した人・PIN 未確認は 403 で弾かれ、画面には「担当者を選び直してください」と出ます）。辞めた人は「停止」（過去の記録は残る）。一覧が空なら今まで通り自由入力です。

### N. 表記の辞書（メーカー・ブランド・カテゴリを揃える）
- PC「設定」タブ → **表記の辞書**（管理画面の「辞書」からも）。「届く表記 → 揃える表記」を登録すると、**取り込み・スマホ編集の保存時に自動で当たり**、「既存の商品に適用」で登録済みの分も揃います。カテゴリは「大 > 中 > 小」の各段にも当たります。
- 「まとめて貼り付ける」で `maker,㈱アリミノ,アリミノ` の形で一気に登録できます。複数ディーラーに広げるときの「SEAM 共通カテゴリ」の対応表として使えます。

### P. 連写・音声・ホーム画面（スマホ）
- ガイド付きカメラの **「連写: ON」** … シャッター → 1 秒で自動登録 → 次の枠へ。5 枚そろうと（撮影キュー中なら）送信が終わり次第、次の商品へ。自動チェックの注意が出たときだけ止まって聞きます。設定は端末に残ります。
- **「🎤 音声」**（Android Chrome など対応ブラウザだけ表示）… 「つぎ」「はい」「シャッター」で撮影／登録、「とりなおし」「もどる」で撮り直し。両手が商品でふさがるとき用。
- **ホーム画面に追加** … 初回に案内が出ます（Android は「追加する」、iPhone は共有 → ホーム画面に追加）。全画面で開き、URL を打たずに済みます。

### Q. 電波が切れたとき（送信待ち）
- 写真の送信がネットワークで失敗すると、端末に一時保存して枠に「送信待ち」と出ます。電波が戻ると（20 秒ごと・回線復帰時）自動で送り、ヘッダの「送信待ち N」が消えます。アプリを閉じても端末に残ります。
- 商品の呼び出し（JAN 読み取り）は電波が必要です。棚の奥へ行く前に商品を開いておくと、写真だけは電波なしでも撮り続けられます。

### R. JAN が無い商品（仮コード）
- スマホのスキャン画面の **「JAN が無い商品を登録する」**、PC 商品一覧の **「JAN が無い商品を登録」** で、`20` で始まる 13 桁の仮コードを自動で振ります（社内コードの範囲・チェックデジット付き）。
- PC 商品一覧で商品を選んで **「ラベル（バーコード）を印刷」** → `pim/labels.html` に EAN-13 のラベルが並びます（A4・2〜3 列のラベルシール向け）。棚に貼れば、スマホでそのまま読めます。普通の JAN の商品も同じように印刷できます。

### S. 列合わせの記憶・受信箱（メール／共有フォルダから自動取り込み）
- **列合わせの記憶** … 同じ見出しのファイルを前に取り込んでいれば、次に開いたときに列合わせ・税区分・送り元・更新列を自動で当てて「前回の設定を適用」と出ます（確認 → 保存の 2 クリック）。
- **自動取り込み用 URL** … PC「設定」→「自動取り込み用 URL」を発行。ここに CSV を POST すると「取り込み」タブの **受信箱** に届き、前に取り込んだことのある見出しなら**自動で取り込まれます**（新規は追加、登録済みと被る JAN は上書きせず注意へ、ファイル内の重複も注意へ）。初めての見出し・Excel は受信箱に置かれるので「取り込む」で列を合わせてください（次回から自動）。
  - 共有フォルダ／社内 PC から: `curl -F file=@商品.csv "<URL>"`（監視スクリプトや Power Automate でも同じ）
  - **メール転送**（無料・SEAM 側で 1 回設定）: Cloudflare ダッシュボード → seam.site → Email → Email Routing を有効化 → Workers に `workers/pim-inbox-email.js` を deploy → Routing rules で「csv@seam.site → Worker」。Worker の `ROUTES` にディーラーの URL を書く（宛先アドレスごとにディーラーを分けられます）。メーカーには「CSV を csv@seam.site に送ってください」と伝えるだけ。
- URL が漏れたら「再発行」で古い URL は無効。受信箱に届いたファイルは D1 に保存されます（1.4MB まで。大きい CSV は PC から）。

### T. 一括編集・同じ写真の検出・サムネ
- PC 商品一覧で **チェック → 「まとめて変更」** … メーカー・ブランド・カテゴリ・単位・税区分・税率を一括で。税区分を変えると税抜/税込を計算し直します。
- 写真を登録するとき **写真の指紋（ハッシュ）** を保存し、**同じ写真が別の商品に入ったら** その場で「⚠ 同じ写真が JAN … にも」と出します。検品タブの「同じ写真が別の商品に」で一覧できます（撮り間違い・貼り間違い）。
- 写真は **300px のサムネ** も自動で作ります: `…/pim-img/products/<番号>/<JAN>/<枚目>_s.webp`。EC の一覧・スマホの表示に。`products` / `export?format=json` の `thumb_url` に入ります。

### U. 日報メール・アカウント設定（PC「設定」タブ・ディーラー本人が変えられるもの）
- **日報・通知メール** … 送り先（10 件まで）と「毎朝送る」の ON/OFF。「昨日の日報を見る」で内容を確認できます（写真枚数・担当者別・全体の進み・メーカー別の残り・残り日数）。
- 送信は GitHub Actions（`.github/workflows/pim-daily-report.yml`・毎朝 7 時）。SEAM 側で GitHub の Secrets に `PIM_ADMIN_KEY`（Cloudflare の ADMIN_KEY と同じ）と SMTP（Gmail のアプリパスワードで可・無料）を入れると動きます: `SMTP_HOST=smtp.gmail.com SMTP_PORT=465 SMTP_USER=xxx@gmail.com SMTP_PASS=<アプリパスワード> MAIL_FROM=xxx@gmail.com`。未設定なら何もしません。
- **ディーラー名・ログイン ID** … ログイン ID は今のパスワードで確認し、変えると全端末で再ログイン。
- **EC 連携キー・Webhook・自動取り込み用 URL** … 管理画面に頼らず本人が発行・無効化できます（管理画面からも可）。
- **担当者一覧・辞書** は M・N の通り。

### O. 取り込みの取り消し（ロールバック）
- 「取り込み履歴」の **「取り消す」** で、その取り込みで **新しく入った商品を消し**、**上書きした商品を取り込み前の内容に戻し** ます（元CSVの行も戻る）。更新取り込みも同じ。
- その取り込みの後に **写真が付いた商品は消しません**（撮影の成果を失わないため）。取り込み後にスマホで直した内容は、取り消すと取り込み前に戻ります（確認ダイアログに出ます）。その取り込みで積んだ未解決の注意は自動で閉じます。取り消しは 1 回だけ（2 人が同時に押しても 1 回だけ走ります）。

## アカウントとパスワード

| したいこと | 誰が | どこで |
|---|---|---|
| ディーラーを追加する | SEAM | `/pim/admin.html` → 発行 |
| パスワードを変える（スタッフが辞めた など） | ディーラー自身 | スマホ: 右上「設定」→ パスワードを変更 ／ PC: 「設定」タブ。**変更した瞬間に、ほかの端末は全部ログアウト**され、新しいパスワードでの再ログインが必要になります |
| パスワードを忘れた | SEAM | `/pim/admin.html` → 「PW再設定」（新しいパスワードが表示されるのでディーラーへ伝える） |
| 契約終了などで止める | SEAM | `/pim/admin.html` → 「停止」（ログイン不可・全端末ログアウト。データは残る。「再開」で戻せる） |
| パスワードはそのまま、全端末を一度ログアウトさせたい | SEAM | `/pim/admin.html` → 「全端末ログアウト」 |

- ログインは端末に記憶され、180日で期限切れになります（再ログイン）。
- 10回続けて失敗すると15分ロックされます（総当たり対策）。管理画面の「PW再設定」でロックも解けます。
- パスワードは PBKDF2-SHA256（10万回）でハッシュ化して保存し、平文は残しません。

## 複数人で同時に登録するとき

ログイン時に **担当者名** を入れます（端末に記憶）。誰が入れた商品・写真・判断かが残り、商品一覧や注意の画面に出ます。
同時に触っても壊れないように、次のように動きます。

| 場面 | 動き |
|---|---|
| 2人が撮影キューで同じ商品を撮ろうとする | 誰かが開いている商品は10分間「撮影中」になり、他の人のキューには出ません。JAN を読んで直接開いた場合は「〇〇さんもこの商品を開いています」と表示（止めはしません） |
| 2人が同じ商品に同時に写真を入れる | 空の枠をタップしたときは番号をサーバが確定します（空いている一番若い番号）。お互いの写真を上書きしません。5枚を超えると「5枚までです」 |
| 他の人が写真や商品情報を変えた | 商品画面は15秒ごと、および画面に戻ったときに最新を取り込みます（「〇〇さんの変更を取り込みました」） |
| 2人が同じ商品の情報を同時に編集 | 先に保存した人が勝ちます。後の人には「〇〇さんが先に更新しました」と出て最新の内容が表示されるので、見てから直します |
| 2人が同じ未登録 JAN を同時に新規登録 | 先の人だけ登録されます。後の人にはその内容が表示されます |
| 2人が別々の CSV を同時に取り込み、同じ JAN が両方に新規としてある | 先の人だけ登録され、後の人の分は上書きせず「注意（登録済みと重複）」に回ります。取り込みログにも件数が出ます |
| 2人が同じ「注意」を同時に処理 | 先に押した人の判断だけが通ります。後の人には「他の人が先に処理しました」と出ます |
| 写真の削除と同時に他の人が追加 | 削除後の詰め直しで他の人の写真を潰さないよう、詰め先が埋まっていたら詰めません |

### iPhone について
- iPhone / iPad の Safari は canvas で webp を作れないため、同梱の wasm 版エンコーダ（`vendor/webp/`）で変換します。Android / PC は canvas で変換します。どちらでも保存されるのは webp だけです。

ディーラーとしては `x-seam-token: <ログインで得たトークン>`、SEAM 側からは `x-seam-key: <ADMIN_KEY>` + `x-seam-account: <ディーラーのID>` を付けます（画像配信 `/pim-img/*` だけ不要）。`x-seam-user: <担当者名(URLエンコード)>` を付けると記録に残ります。

| メソッド | パス | 用途 |
|---|---|---|
| POST | `/api/pim/auth/login` `{login_id, password}` | ログイン → `{token, account}` |
| GET | `/api/pim/auth/me` | 今のアカウント |
| POST | `/api/pim/auth/password` `{current, password}` | パスワード変更（全端末ログアウト・新トークンを返す） |
| GET/POST | `/api/pim/admin/accounts` | （管理キー）一覧 / `action: create, reset, disable, enable, logout_all, rename, api_key, api_key_revoke, webhook{url}, webhook_clear, webhook_test` |

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/api/pim/status` | 件数・設定状態 |
| GET | `/api/pim/products?jan=…` / `?q=…&maker=…&noimg=1&limit=&offset=` | 商品1件 / 一覧 |
| PUT | `/api/pim/products` | 商品1件の登録・更新（JSON）。`expected_updated_at` を付けると楽観ロック（他の人が先に更新していれば 409）。`insert_only:1` で「無いときだけ登録」 |
| DELETE | `/api/pim/products?jan=…` | 削除（画像も） |

| GET/POST | `/api/pim/dict` | 表記の辞書 / `action: set{kind,src,dst}, bulk{rows}, delete{id}, apply` |

## 実証実験の前に（デプロイ後の確認手順・10分）

1. **Functions が生きているか**: ブラウザで `https://seam.site/api/pim/status` を開く → `{"ok":false,"reason":"unauthorized"...}` と出れば OK（`no_db` なら D1 未設定、HTML が返るなら Functions 未デプロイ）。
2. **管理画面**: `/pim/admin.html` → 管理キーでログイン → テスト用アカウントを1つ発行（例: `test-dealer`）。
3. **PC 取り込み**: `/pim/import.html` → そのアカウントでログイン → 手元の CSV を取り込む → 「商品一覧」で見える。
4. **スマホ**: `/pim/` → 同じアカウントでログイン → 商品のバーコードを読む → ガイド付きカメラで1枚撮る → 上に大きく表示される → PC の商品一覧でも写真が見える。
5. **出力**: 「出力」タブ → CSV をダウンロード → Excel で開いて画像 URL をブラウザで開ける。
6. うまくいったら本番用のディーラーアカウントを発行し、テスト用は「停止」。

### Cloudflare のプランについて（重要）
- Workers/Pages Functions の **Free プランは 1リクエストあたり CPU 10ms** です。5,000件超の CSV 出力やログイン（パスワードのハッシュ計算）は超えることがあり、その場合 **Error 1102（Worker exceeded resource limits）** になります。実証実験でこれが出たら **Workers Paid（月 $5・CPU 30秒）** に上げてください。診断ダッシュボードの集計 API と同じ条件です。
- D1・R2 は Free 枠で十分（商品1万件・写真5万枚でも数十MB〜数GB）。

### 現場で起きやすいこと
| 症状 | 原因と対処 |
|---|---|
| カメラが真っ黒／起動しない | サイト設定でカメラが「拒否」。iPhone: 設定 → Safari → カメラ → 許可。「カメラ再起動」を押す。JAN 手入力でも進める |
| バーコードを読まない | 明るい場所で、枠にバーコード全体を入れて 10〜20cm。反射するパッケージは角度を変える。JAN 手入力でも進める |
| 「webp 変換部品を読み込めません」 | 通信が不安定。電波の良い所でもう一度。iPhone は iOS 15 以降の Safari |
| 「パスワードが変更されたか、ログインの期限が切れました」 | 誰かがパスワードを変えた／SEAM が再設定した。新しいパスワードで再ログイン |
| 「〇〇さんが先に更新しました」 | 同じ商品を同時に編集した。表示された最新を見て直す |
| 写真の背景が白くならない | 白い紙・シートの上で撮っていない。または影が濃い → 撮影画面の「背景を白に: 強」 |
| 「5枚までです」 | 別の人が同時に入れて埋まった。写真をタップして差し替える |

## 困ったとき

- **「保存先の設定がまだです」** … D1 binding `DB` が無い。①を確認。
- **「パスワードが変更されたか、ログインの期限が切れました」** … 誰かがパスワードを変えた／SEAM が再設定・停止した／180日経った。新しいパスワードでログインし直す。
- **写真だけ保存できない** … R2 binding `PRODUCT_IMAGES` が無い。②を確認。
- **カメラが起動しない** … ブラウザのサイト設定で seam.site のカメラを「許可」に。iPhone は Safari 推奨。JAN は手入力でも呼び出せます。
- **JAN が `4.90128E+12` のように壊れている** … Excel が数値として保存したもの。取り込みで注意になります。元データを「文字列」列にして出し直してもらうか、Excel のまま（.xlsx）送ってもらえば正しく読めます。
- **同じ JAN が2つある** … 登録されず「注意」に積まれます。「注意」タブでどちらを残すか選んでください。
