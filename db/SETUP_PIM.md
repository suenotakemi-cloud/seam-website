# SEAM 商品マスタ統一（PIM）— 設定手順と使い方

メーカーごとにバラバラな形式で届く商品データ（CSV / Excel）を、
**JAN・商品名・価格・税込/税抜・内容量・画像(最大5枚・webp)** の1つの形に揃えて保存し、
同じ形で出力する仕組みです。スマホで JAN を読んで写真を登録する画面も含みます。

- スマホ登録: **https://seam.site/pim/**（JANスキャン → 商品呼び出し → 写真5枚）
- PC 取り込み・出力: **https://seam.site/pim/import.html**
- SEAM 管理（ディーラーアカウントの発行）: **https://seam.site/pim/admin.html**
- どれも検索エンジンには出ません（noindex）。
- **1ディーラー = 1アカウント（ID + パスワード）**。ディーラーのスタッフは全員同じ ID を使い、端末ごとに担当者名を名乗ります。商品・写真・注意はアカウントごとに完全に分かれ、他のディーラーのデータは見えません。
- 管理画面だけは診断ダッシュボードと同じ `ADMIN_KEY` でログインします。

---

## 仕組み（全体像）

```
メーカーCSV/Excel ─▶ pim/import.html（列を合わせて統一形に整形・JAN重複を検出）
                          │  保存                     │ 注意（重複は登録しない）
                          ▼                           ▼
                    D1 seam-db: pim_products     D1: pim_issues → 画面で「どちらを残す」
                          ▲
スマホ pim/index.html ─ JAN読取 → 商品呼び出し → 写真（何形式でも webp に変換）→ R2 PRODUCT_IMAGES
                          │
                          ▼
                    /api/pim/export → 統一CSV / JSON（画像は https://seam.site/pim-img/… のURL）
```

コード側（`db/pim-schema.sql` / `functions/api/pim/*` / `functions/pim-img/` / `pim/*.html` / `js/pim-*.js`）はデプロイ済みです。
あとは **Cloudflare 側で保存先を繋ぐ設定だけ** が必要です。

## 設定手順（Cloudflare ダッシュボード）

### ① D1（商品台帳）— 診断ダッシュボードで作った `seam-db` をそのまま使う
- まだ無ければ `db/SETUP_DASHBOARD.md` の①〜③を先に。
- テーブルは **初回アクセス時に自動で作られます**（`CREATE TABLE IF NOT EXISTS`）。
  手動で入れたい場合は `seam-db` → **Console** に `db/pim-schema.sql` を貼って Execute。

### ② R2（画像の実体）を作る
1. Cloudflare → **R2 Object Storage** → **Create bucket** → 名前 **`seam-product-images`**
2. **Workers & Pages** → サイト **seam-website** → **Settings** → **Functions** → **R2 bucket bindings** → **Add binding**
   - Variable name: **`PRODUCT_IMAGES`**（大文字・この名前のまま）
   - R2 bucket: `seam-product-images`
3. 保存

> R2 が未設定でも商品データの取り込み・出力は動きます。写真の保存だけができません（画面に案内が出ます）。

### ③ 管理キー
- 診断ダッシュボードの **`ADMIN_KEY`**（Environment variables）をそのまま使います。未設定なら `db/SETUP_DASHBOARD.md` の④。
- ログインのトークンはこの鍵で署名します。別にしたければ **`PIM_SECRET`**（長いランダム文字列）を足してください（足すと既存のログインは全部無効になります）。

### ③-2 ディーラーのアカウントを発行する
1. `/pim/admin.html` を管理キーで開く
2. 「アカウントを発行する」に ID（英数字）・ディーラー名・初期パスワード（自動生成可）を入れて発行
3. 表示された ID とパスワードを、`/pim/`（スマホ）と `/pim/import.html`（PC）の URL と一緒にディーラーへ安全な方法で伝える
- 新しいディーラーが増えたら、同じ手順で発行するだけです。

### ④ 再デプロイ
- **Deployments** → 最新の **⋯** → **Retry deployment**（または次回の push で自動反映）

### （任意）webp 以外が届いたときのサーバ側変換
- ブラウザ側で必ず webp に変換して送るので通常は不要です。
- 古い端末からの保険として、Cloudflare Images の **Images binding**（Variable name `IMAGES`）を足すと、サーバ側でも変換します。

## 使い方

### A. メーカーの CSV / Excel を取り込む（PC）
1. `/pim/import.html` → **取り込み** タブ → ファイルをドロップ
   - 文字コード（UTF-8 / UTF-16 / Shift_JIS）・区切り（カンマ / タブ）・Excel のシートは自動判定
2. **列を合わせる** … 見出しの言葉が違っても自動で当てます（例: 「EC表示名」→商品名、「標準売上単価」→価格、「上代単価」→上代）。違っていれば直す。
   - 価格列が税込か税抜かは、列名・値に「税込/税抜」があればそれを優先。無ければここで選ぶ。
   - 内容量の列が無いときは、商品名の「250ml」「1Kg」などから取り出します。単位なしの数字（「〇〇 250」）は商品名の語（シャンプー→ml、トリートメント→g）から推定し、**注意** に印を付けます。
3. **確認する** … 揃えた結果の表と、注意の内訳（JANチェックデジット不一致・価格が読めない・単位推定 など）
4. **JANが被っているもの** … 登録済みと同じ JAN / 同じファイル内で重複している JAN を並べて表示。
   - 「登録済みを残す」「届いた方で上書き」「この行を採用」を選ぶ
   - **決めなかったものは登録されず「注意」タブに積まれます**（あとから決められます）
5. **保存** … 300件ずつ保存。履歴が下に残ります。

### B. スマホで写真を登録する（iPhone / Android）
1. `/pim/` を開く（ホーム画面に追加するとアプリのように使えます）→ ディーラーの ID・パスワード・担当者名
2. カメラに商品のバーコードをかざす → 商品が呼び出される。**写真が登録済みなら、上に大きく表示され、サムネイルで切り替え・タップで全画面**（誰が撮ったか・サイズも表示）。未登録の JAN なら商品名だけ入れて登録 → そのまま写真へ（**新商品はこの流れで随時追加できます**）
3. 写真の枠をタップ → **「カメラで撮る」か「写真・ファイルから選ぶ」** → 1枚保存されると次の枠が光る → 繰り返し（最大5枚・1枚目がメイン）
4. **次の商品をスキャン**
- 写真は端末側で長辺 1600px・webp に変換してから送るので、通信量も保存形式も揃います。
- 写真をタップ → 撮り直し / 差し替え / 削除（削除すると後ろの写真が前に詰まります）

### B-2. 写真を揃えるしくみ（ガイド付きカメラ・白背景）
- 枠をタップ → **「ガイド付きカメラで撮る」** でアプリ内のカメラが開き、次の目印が重なります。
  - 外枠 … 保存される範囲（正方形）
  - 黄色の点線 … 商品を収める範囲（縦 78%・横 70%）。ここいっぱいに入れると、どの商品も同じ大きさに写ります
  - 下の黄色い線 … 商品の底を合わせる位置
  - 商品のシルエット … ボトル / ジャー・缶 / チューブ・袋 / 枠のみ から選べます（端末に記憶）
  - 「↑ キャップ・上を上に」・中心線・水平器（端末の傾きを表示。対応端末のみ）
  - 何枚目かで指示が変わります: 1 正面 / 2 裏面（成分表示）/ 3 斜め・側面 / 4 キャップ・口元 / 5 手に持って大きさ
- 保存は必ず **1200×1200 の正方形** です。アルバムの写真やメーカーの画像も、白で余白を足して正方形にします。
- **背景を白に**（標準 / 強 / 弱 / なし）… 白い紙・シートの上で撮る前提で、縁からつながる「ほぼ白」の部分を純白にし、紙の色かぶり（黄み・青み）も補正します。影が残るときは「強」に。背景が白くない写真は判定して触りません。
  - これは AI の切り抜きではありません。柄のある背景や机の上で撮ると白くなりません。**必ず白い紙・白いシートの上で撮ってください**。
  - AI による完全な切り抜き（remove.bg などの外部サービス）が必要になったら、サーバ側に組み込めます（有料・別途）。
- 端末のカメラアプリで撮りたいときは撮影画面の「端末カメラ」から。その場合も正方形・白背景の加工はかかりますが、構図は自分で合わせることになります。

### C. メーカーから届いた画像フォルダをまとめて登録（PC）
- **画像まとめ登録** タブにフォルダの中身をドロップ。ファイル名の JAN と枚目を読みます。
  - `4901275230122.jpg` → 1枚目 / `4901275230122_2.png` / `4901275230122-3.jpeg` / `4901275230122 (4).heic`
  - 同じ JAN で枚目の無いファイルが複数あれば、名前順に 1, 2, 3… と入ります
- jpg / png / gif / bmp / webp / avif / heic（Safari）…何で来ても保存は webp。既定で正方形 1200px・白背景に揃えます（画面のチェックで外せます）。

### D. 出力する
- **出力** タブ → CSV（Excel で開ける UTF-8 BOM 付き）または JSON。メーカー・写真あり/なしで絞れます。
- 列（固定）: `JAN, 商品名, 価格(税抜), 価格(税込), 入力価格の税区分, 税率(%), 内容量, 単位, 内容量表記, 上代(税抜), 仕入価格, メーカー, ブランド, カテゴリ, 商品説明, 元商品コード, 画像1〜5, 画像枚数, 更新日時`
- 画像は `https://seam.site/pim-img/products/<アカウント番号>/<JAN>/<枚目>.webp?v=…` の URL。EC 側からそのまま参照できます（CORS 許可済み）。

## アカウントとパスワード

| したいこと | 誰が | どこで |
|---|---|---|
| ディーラーを追加する | SEAM | `/pim/admin.html` → 発行 |
| パスワードを変える（スタッフが辞めた など） | ディーラー自身 | スマホ: 右上「設定」→ パスワードを変更 ／ PC: 「設定」タブ。**変更した瞬間に、ほかの端末は全部ログアウト**され、新しいパスワードでの再ログインが必要になります |
| パスワードを忘れた | SEAM | `/pim/admin.html` → 「PW再設定」（新しいパスワードが表示されるのでディーラーへ伝える） |
| 契約終了などで止める | SEAM | `/pim/admin.html` → 「停止」（ログイン不可・全端末ログアウト。データは残る。「再開」で戻せる） |
| パスワードはそのまま、全端末を一度ログアウトさせたい | SEAM | `/pim/admin.html` → 「全端末ログアウト」 |

- ログインは端末に記憶され、180日で期限切れになります（再ログイン）。
- 10回続けて失敗すると15分ロックされます（総当たり対策）。管理画面の「PW再設定」でロックも解けます。
- パスワードは PBKDF2-SHA256（10万回）でハッシュ化して保存し、平文は残しません。

## 複数人で同時に登録するとき

ログイン時に **担当者名** を入れます（端末に記憶）。誰が入れた商品・写真・判断かが残り、商品一覧や注意の画面に出ます。
同時に触っても壊れないように、次のように動きます。

| 場面 | 動き |
|---|---|
| 2人が同じ商品に同時に写真を入れる | 空の枠をタップしたときは番号をサーバが確定します（空いている一番若い番号）。お互いの写真を上書きしません。5枚を超えると「5枚までです」 |
| 他の人が写真や商品情報を変えた | 商品画面は15秒ごと、および画面に戻ったときに最新を取り込みます（「〇〇さんの変更を取り込みました」） |
| 2人が同じ商品の情報を同時に編集 | 先に保存した人が勝ちます。後の人には「〇〇さんが先に更新しました」と出て最新の内容が表示されるので、見てから直します |
| 2人が同じ未登録 JAN を同時に新規登録 | 先の人だけ登録されます。後の人にはその内容が表示されます |
| 2人が別々の CSV を同時に取り込み、同じ JAN が両方に新規としてある | 先の人だけ登録され、後の人の分は上書きせず「注意（登録済みと重複）」に回ります。取り込みログにも件数が出ます |
| 2人が同じ「注意」を同時に処理 | 先に押した人の判断だけが通ります。後の人には「他の人が先に処理しました」と出ます |
| 写真の削除と同時に他の人が追加 | 削除後の詰め直しで他の人の写真を潰さないよう、詰め先が埋まっていたら詰めません |

### iPhone について
- iPhone / iPad の Safari は canvas で webp を作れないため、同梱の wasm 版エンコーダ（`vendor/webp/`）で変換します。Android / PC は canvas で変換します。どちらでも保存されるのは webp だけです。

## API（EC 側と連携するとき）

ディーラーとしては `x-seam-token: <ログインで得たトークン>`、SEAM 側からは `x-seam-key: <ADMIN_KEY>` + `x-seam-account: <ディーラーのID>` を付けます（画像配信 `/pim-img/*` だけ不要）。`x-seam-user: <担当者名(URLエンコード)>` を付けると記録に残ります。

| メソッド | パス | 用途 |
|---|---|---|
| POST | `/api/pim/auth/login` `{login_id, password}` | ログイン → `{token, account}` |
| GET | `/api/pim/auth/me` | 今のアカウント |
| POST | `/api/pim/auth/password` `{current, password}` | パスワード変更（全端末ログアウト・新トークンを返す） |
| GET/POST | `/api/pim/admin/accounts` | （管理キー）一覧 / `action: create, reset, disable, enable, logout_all, rename` |

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/api/pim/status` | 件数・設定状態 |
| GET | `/api/pim/products?jan=…` / `?q=…&maker=…&noimg=1&limit=&offset=` | 商品1件 / 一覧 |
| PUT | `/api/pim/products` | 商品1件の登録・更新（JSON）。`expected_updated_at` を付けると楽観ロック（他の人が先に更新していれば 409）。`insert_only:1` で「無いときだけ登録」 |
| DELETE | `/api/pim/products?jan=…` | 削除（画像も） |
| POST | `/api/pim/import` | 取り込み（`action: check / begin / commit / finish`） |
| GET/POST | `/api/pim/issues` | 注意の一覧 / 解決 |
| GET/POST/DELETE | `/api/pim/images?jan=…&slot=…` | 画像の一覧 / 登録(multipart, webp。`slot=auto` で空き番号をサーバが確定) / 削除 |
| GET | `/api/pim/export?format=csv\|json&maker=&only_images=1&noimg=1` | 統一フォーマット出力 |

## 実証実験の前に（デプロイ後の確認手順・10分）

1. **Functions が生きているか**: ブラウザで `https://seam.site/api/pim/status` を開く → `{"ok":false,"reason":"unauthorized"...}` と出れば OK（`no_db` なら D1 未設定、HTML が返るなら Functions 未デプロイ）。
2. **管理画面**: `/pim/admin.html` → 管理キーでログイン → テスト用アカウントを1つ発行（例: `test-dealer`）。
3. **PC 取り込み**: `/pim/import.html` → そのアカウントでログイン → 手元の CSV を取り込む → 「商品一覧」で見える。
4. **スマホ**: `/pim/` → 同じアカウントでログイン → 商品のバーコードを読む → ガイド付きカメラで1枚撮る → 上に大きく表示される → PC の商品一覧でも写真が見える。
5. **出力**: 「出力」タブ → CSV をダウンロード → Excel で開いて画像 URL をブラウザで開ける。
6. うまくいったら本番用のディーラーアカウントを発行し、テスト用は「停止」。

### Cloudflare のプランについて（重要）
- Workers/Pages Functions の **Free プランは 1リクエストあたり CPU 10ms** です。5,000件超の CSV 出力やログイン（パスワードのハッシュ計算）は超えることがあり、その場合 **Error 1102（Worker exceeded resource limits）** になります。実証実験でこれが出たら **Workers Paid（月 $5・CPU 30秒）** に上げてください。診断ダッシュボードの集計 API と同じ条件です。
- D1・R2 は Free 枠で十分（商品1万件・写真5万枚でも数十MB〜数GB）。

### 現場で起きやすいこと
| 症状 | 原因と対処 |
|---|---|
| カメラが真っ黒／起動しない | サイト設定でカメラが「拒否」。iPhone: 設定 → Safari → カメラ → 許可。「カメラ再起動」を押す。JAN 手入力でも進める |
| バーコードを読まない | 明るい場所で、枠にバーコード全体を入れて 10〜20cm。反射するパッケージは角度を変える。JAN 手入力でも進める |
| 「webp 変換部品を読み込めません」 | 通信が不安定。電波の良い所でもう一度。iPhone は iOS 15 以降の Safari |
| 「パスワードが変更されたか、ログインの期限が切れました」 | 誰かがパスワードを変えた／SEAM が再設定した。新しいパスワードで再ログイン |
| 「〇〇さんが先に更新しました」 | 同じ商品を同時に編集した。表示された最新を見て直す |
| 写真の背景が白くならない | 白い紙・シートの上で撮っていない。または影が濃い → 撮影画面の「背景を白に: 強」 |
| 「5枚までです」 | 別の人が同時に入れて埋まった。写真をタップして差し替える |

## 困ったとき

- **「保存先の設定がまだです」** … D1 binding `DB` が無い。①を確認。
- **「パスワードが変更されたか、ログインの期限が切れました」** … 誰かがパスワードを変えた／SEAM が再設定・停止した／180日経った。新しいパスワードでログインし直す。
- **写真だけ保存できない** … R2 binding `PRODUCT_IMAGES` が無い。②を確認。
- **カメラが起動しない** … ブラウザのサイト設定で seam.site のカメラを「許可」に。iPhone は Safari 推奨。JAN は手入力でも呼び出せます。
- **JAN が `4.90128E+12` のように壊れている** … Excel が数値として保存したもの。取り込みで注意になります。元データを「文字列」列にして出し直してもらうか、Excel のまま（.xlsx）送ってもらえば正しく読めます。
- **同じ JAN が2つある** … 登録されず「注意」に積まれます。「注意」タブでどちらを残すか選んでください。
